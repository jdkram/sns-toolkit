# Quick wins: day-of-week motifs (9.133), hub thumbnail (9.135), top tags (9.136) — unreleased

Three independent XS features shipped together. Test each section independently.

---

## 9.135 — Event hub: original image + thumbnail preview side-by-side

- [ ] Open the event hub for any event that has an image. Confirm two images are shown: "Original" (the editpreview, wider) and "Card thumbnail" (capped at 120px, the indexview crop).

- [ ] For an event whose image has a crop box set (via the crop tool): confirm the "Card thumbnail" reflects the crop, not just a scaled-down full image.

- [ ] For an event with no image: confirm both the "Original" and thumbnail slots are absent and "No image yet" is still shown (no broken-image icons).

- [ ] For an event whose image has letterbox bars set (bar_colour field): confirm the thumbnail shows the bars.

- [ ] On a narrow viewport (mobile): confirm the two images stack vertically rather than overflowing horizontally (the outer `d-flex flex-wrap` should handle this).

---

## 9.136 — Top-5 most-used tags surfaced at the top of the tag picker

- [ ] Open the edit form for any event. Confirm the tag picker has two labelled groups: "Common tags" (up to 5 tags) then "All tags" (every tag, alphabetically as before). Confirm "All tags" starts on its own line with a top border separating it from "Common tags".

- [ ] The tags in the "Common tags" group should be the 5 most frequently used across all events — check these look plausible against the actual programme data.

- [ ] The top-5 tags appear in **both** groups. Clicking a pill in "Common tags" toggles the corresponding pill in "All tags" and vice versa — they stay in sync. (The "Common tags" pills are visual clones that delegate to the real checkboxes in "All tags".)

- [ ] Submitting the form saves the selected tags correctly. There should be no duplicate submissions or phantom tags — the clone inputs have `name=""` so only the originals in "All tags" are submitted.

- [ ] If a tag is already selected on the event when the page loads, its pill appears pre-selected in **both** groups.

- [ ] On a fresh seed database with few events, if fewer than 5 non-archived tags exist, the "Common tags" group shows what's there with no errors.

- [ ] Tag description tooltips (hover on a tag badge): confirm they still appear on tags in both groups.

## 9.133 — Day-of-week filter row on programme page (public site)

- [ ] Visit the public programme page (`/`). Confirm a second filter row ("Any day / Mon / Tue / Wed / Thu / Fri / Sat / Sun") appears below the type filter row, separated by a faint top border.

- [ ] Click "Tue": only Tuesday events remain visible. Click "Any day": all events return. Confirm the active button is visually highlighted and "Any day" highlights when no day is selected.

- [ ] Day filter + type filter AND logic: select "Film" then click "Sat" — only Saturday film events should be visible.

- [ ] Day filter + text search AND logic: type "music" in the search box, then click "Fri" — only Friday events matching "music" should be visible.

- [ ] "Clear" button resets all three filters (search, type, day) simultaneously.

- [ ] URL persistence: select Sat, reload the page — the Sat button should be active and the grid filtered. Params: `?dow=6`.

- [ ] On mobile: the day filter row scrolls horizontally if it overflows (same behaviour as the type filter row). No horizontal overflow on the page.

- [ ] Confirm the day filter does **not** appear on the Cube Microplex public template (only in `star_and_shadow_templates/view_showing_index.html`).
